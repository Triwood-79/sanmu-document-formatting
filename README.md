# 通用公文排版 Skill

把纯文本、Markdown 或已有 DOCX 整理成排版统一的 Word 文档。你只需要把文字或文件交给 AI Agent，并说明想做什么，不需要会写代码。

**不改写正文｜不覆盖原文件｜先确认结构再排版｜不静默安装依赖或字体**

最常见的流程只有三步：提供文字或 DOCX → 确认识别结果 → 获得新的 DOCX。

> 当前状态：V1 发布候选版。

## 30 秒开始

### 一行命令安装

```bash
npx -y skills add https://github.com/Triwood-79/official-document-formatting -g --skill official-document-formatting --copy
```

安装器会检测本机已有的 Agent，并让你选择安装目标。该命令需要 Node.js；`-g` 表示安装到用户级目录，`--copy` 可以避免 Windows 符号链接权限问题。

### 也可以直接发给你的 Agent

```text
帮我安装通用公文排版 Skill：
https://github.com/Triwood-79/official-document-formatting

请安装到当前 Agent 的个人 Skills 目录。若已存在同名 Skill，请先告诉我，不要直接覆盖。
```

安装完成后，可以直接说：

```text
使用通用公文排版 Skill，把这份 DOCX 检查并重新排版。
```

若当前 Agent 支持 `$skill-name` 显式调用，也可以使用 `$official-document-formatting`。已经安装过的话，重新运行安装命令即可更新。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 从文字生成 Word | 接受纯文本或 Markdown，识别主标题、标题、正文、说明、落款和补充参考资料后生成 DOCX。 |
| 重新排版已有文档 | 先展示段落分类、表题候选、表头层数和风险，再经用户确认后处理。 |
| 记住单位格式 | 只有用户主动修改并发送“确认保存”后，个性化排版参数才会长期生效。 |
| 临时调整一次 | 当前请求中的页边距、打印模式、字体或行距要求只作用于本次文档。 |
| 本地校验与清理 | 输出后清理常见文档元数据，并检查页面、字体、段落、表格和页码结构。 |

Microsoft Word 不是核心排版的必需条件。运行前会检查 Python 和所需组件，发现缺少时会先说明情况并等待确认。安装 Word 或 LibreOffice 后，Agent 可以进一步渲染文档并进行视觉检查；没有渲染器时，只能报告结构验证结果。

## 直接这样用

### 把文字生成 Word 文档

```text
使用 $official-document-formatting，把下面的内容生成排版后的 Word 文档。
只做结构识别和排版，不改写、补写或删减正文。
```

示例内容：

```text
示例标题
某单位
某年某月某日

一、一级标题
这里是正文内容。

（一）二级标题
这里是下一段正文内容。
```

### 重新排版已有 DOCX

```text
使用 $official-document-formatting，检查并重新排版这份 DOCX。
先展示标题、正文、说明内容和表格的识别结果，等我确认后再处理，不要覆盖原文件。
```

输出文件默认命名为：

```text
原文件名_排版后.docx
```

如遇重名会自动增加序号，原文件始终保留。

### 临时改一次格式

```text
使用 $official-document-formatting 处理这份文档。
这一次改成单面打印，正文固定行距 28 pt；不要保存为长期设置。
```

如果当前 Agent 不使用 `$skill-name` 语法，把 `$official-document-formatting` 换成“通用公文排版 Skill”即可。

## 改成自己的固定格式

第一次使用直接采用内置通用格式，不会弹出问卷。需要调整时，对 Agent 发送以下口令：

| 你想做什么 | 发送的口令 |
|---|---|
| 查看现在使用的格式 | `查看当前排版格式` |
| 修改部分参数 | `修改排版格式` |
| 重新填写全部参数 | `重新录入排版格式` |
| 保存修改草稿 | `确认保存` |
| 放弃本次修改 | `取消修改` |
| 恢复内置格式 | `恢复通用公文预设格式` |

修改时，Agent 会分组显示当前值并询问新值；保存前展示“当前值 → 新值”的差异。没有收到 `确认保存`，原来的长期设置不会改变。

排版参数的优先级是：**当前文档的临时要求 > 已确认保存的个人格式 > 内置通用格式**。

### 内置格式概览

- A4 纵向，默认双面打印。
- 主标题使用小标宋风格，一级标题使用黑体，二级标题使用楷体，正文使用仿宋。
- 正文默认三号字、首行缩进 2 字符、固定行距 30 pt、两端对齐。
- 纳入编排的段落关闭孤行控制。
- 主标题与正文之间自动保留一个独立空行；文末单位、日期分行，在右侧共用中轴居中，位置随文字长度调整，并与末段空一行。
- 数字和英文使用 Times New Roman。
- 页码采用 `— 1 —` 样式；双面打印时位于页面下方外侧，单面打印时居中。

完整内置参数以 [`assets/presets/generic_official_v1.json`](./assets/presets/generic_official_v1.json) 为准，README 只保留便于快速理解的概览。

## 支持范围与边界

| 状态 | 内容 |
|---|---|
| ✅ 支持 | 新建或重新排版 `.docx`；识别标题层级和文末落款；统一普通文字和表格字体；保存个人格式；结构验证；元数据清理。 |
| ⚠️ 有限支持 | 图片、文本框和特殊横向页面会保留，但不统一其内部格式。 |
| ❌ 不支持 | 直接处理 `.doc`、`.docm`、扫描件和 PDF；补写事实内容；版记编排；重新设计复杂表格或图文版面。 |

处理已有文档时还需注意：

- 带批注、修订、加密或文档保护的文件，需要先提供已处理完成的干净副本。
- 纳入编排的普通文字会统一为黑色；确认跳过的段落保留原样。
- 表格会统一字体族、文字颜色和全局加粗设置，但保留字号、对齐、行距、边框、底纹、行高和列宽。
- 文末单位、日期按落款编排，原有“印发”等文字保留；其他版记内容可在检查时选择跳过。
- Skill 只负责结构识别和排版，不会自行补写姓名、单位、日期、签章或其他事实。

## 字体与视觉检查

Skill 会优先使用内置预设中的方正字体；缺少首选字体时尝试黑体、楷体_GB2312、仿宋_GB2312、SimSun 等备用字体。首选和备用字体都不可用时，文档仍可以生成，但 Agent 会明确提示当前电脑不能完成对应字体效果的视觉检查。

Skill 不会自动下载或捆绑字体。

## 隐私与安全

- 排版脚本在本机运行，不包含文档上传功能；Agent 平台和模型服务如何处理数据，以相应产品和账号设置为准。
- 长期配置只保存排版参数，不保存正文、姓名、单位、日期、文档路径或输出历史。
- 输出后会清理作者、最后修改者、公司、自定义属性等常见文档元数据。
- 原文件不会被覆盖，方便随时对照和回退。
- 向 GitHub Issues 提交问题前，请先删除真实业务内容，只提供可公开的复现示例。

## 常见问题

### 怎样更新？

重新运行安装命令，或者执行：

```bash
npx -y skills update official-document-formatting -g
```

### 换一台电脑还能使用原来的设置吗？

Skill 可以重新安装，但个人排版配置默认保存在当前电脑，不会跟随 Git 仓库自动同步。需要在新电脑重新录入，或由你明确决定复制配置文件。

### 为什么只有“结构验证通过”，没有“视觉验收通过”？

结构验证检查 DOCX 内部的页面、字体、字号、段落和页码设置。视觉验收还需要 Word 或 LibreOffice 把文档实际渲染出来；缺少渲染器时，Skill 不会把结构检查表述成肉眼效果已经完全正确。

### 为什么不覆盖原文档？

自动识别可能需要人工纠正，复杂 Word 元素也可能保留特殊设置。另存新文件便于对照，也能随时回到原件。
